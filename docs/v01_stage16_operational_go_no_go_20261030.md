# Stage 16 — 運用費用・作業時間削減・限定ベータGo/No-Go監査

2026-10-30時点。**実測とシミュレーションを区別し、全条件を満たすまでRelease No-Go。**

## Modal A10費用の簡易上限モデル（公式単価、実請求ではない）

[Modal公式Pricing](https://modal.com/pricing)の現在の例示単価：A10 `$0.000306/GPU秒`、CPU `$0.0000131/コア秒`、Memory `$0.00000222/GiB秒`。

`beta_modal.py` が要求するA10×1、CPU×2、メモリ8GiBを同時にフル請求するという保守的計算では**$0.00034996/秒**。GPUコンテナが480秒稼働すると**$0.168**、タイムアウト上限3600秒だと**$1.260**。既存の24時間4ジョブまでが毎回3600秒、毎日30日続けば**約$151.18/月**（インフラ計算部分のみ）。CPU使用実績、コンテナの起動/アイドル、ネットワーク、地域、容量、保存、モデルキャッシュ、割引／無料枠、請求方式次第で実請求は変化する。

この値は**モニタリング済み実コストではない**。外部への限定ベータの前には、ModalのWorkspace > Usage and Billingから（a）月額予算と警告、（b）既存利用を含めた請求残高、（c）秘密情報非表示の異常な連続起動検知、（d）一時試験Appが停止・破棄されたことを人間が確認する。アプリ内ではGPU 4件/24h、同時1件、保存2件、ジョブ上限60分を実装済みだが、これは請求ハード上限と同義ではない。

## 利用者時間50%削減の検証プロトコル

機密・個人情報を含まない異なる会議録音を5件以上用意する。同一の録音・同等技能の参加者で「完全手作業」と「Web自動文字起こし＋音声照合・修正」を順序交差で試し、音声を聞き始めてから**意味の通る最終確認済み議事録**を完成させるまでの時間を計測。生成待ち時間を含む値と、修正作業のみの値を分ける。

各録音で全文・話者分離・時刻等の必須品質を最終監査し、未完成・著しい誤りのある結果は時間短縮成功として扱わない。録音単位の時間短縮率を求め、中央値50%以上を暫定ゲートとする。正解原文や音声そのものをCIやGitHubへ保管せず、時間・品質判定・匿名化した録音IDのみ保全する。

**現状：参加者による計測が未実施なので結果は未認証。** AIによる推定・架空の完了時間を代用しない。

## 最終リリース判定

次の一つでも不合格または未検証なら**No-Go**：
- 公開可・許諾済み音声で、時刻付きQwen＋話者統合が全10件の同一参照ハッシュで完成し、発話の欠落や時刻異常が無い
- 新規3〜4話者の自然会議、CER中央値15%以下（暫定）、DER中央値30%以下、話者付きcpCERを独立監査
- 60分Web E2Eで転写→編集→保存→ZIP→音声の最後→削除が複数の異なる入力で再現成功
- Modal実ストレージで24h経過データを削除、期限内の活性ジョブ保護、停滞ジョブの手動回復方針、定期実行・課金上限の運用確認
- 最終文字起こしを仕上げる実測作業時間50%以上削減

限定ベータは認証済み少数の利用者での非機密音声に限定する。研究用IngCrowdはCC BY-NC 4.0で、商用評価へ無断転用しない。PR #4はDraft、mainと既定Whisperを自動変更しない。
