# Stage 38 — A案 Studio UI を採用（2026-10-31）

## 意思決定とスコープ

ユーザーはUI比較からA案「Studio」を選択。非公開v0.1はReact + TypeScript + Viteを継続し、FastAPI + Modal GPU を維持する。Streamlit/ GitHub Pagesには変更しない。実装は既存Draft PR #4内で、デプロイ・一般公開は行わない。

## 画面構成

- 左：ダークなワークスペースナビ／最近の録音。中央：音声同期を重視した発言テキスト編集。右：話者の一括リネームと重複発話確認。下部：常設音声プレーヤーと3秒戻る。
- フラットで明るい作業画面に紺色のサイドバー、アクセントは紫。PCを中心に設計し、狭い画面ではパネルを縦積みにする。
- 編集ツールバー：全文・重複要確認の絞り込み、発言検索、新規発言追加、音声再生に合わせた自動追従ON/OFF。
- 「重複要確認」は**未確認の重複発話推定窓**のみを表示し、一般の発言を人手検証済みと誤表示しない。原音声による確認が必須。
- 話者一括リネーム：インスペクターの鉛筆ボタンで該当話者の全発言だけを修正。別話者への統合は確認ダイアログを出す。変更は従来の保存APIへ明示保存。
- ショートカット：編集中の入力要素では無効にして、Space再生/一時停止、左右矢印3秒移動、Ctrl/Cmd+S保存。本文にカーソルがある場合、矢印は文字移動用のまま。
- ビルド未実施時の既存UIへのフォールバック、同一オリジン認証、CSRF、音声/編集データをLocalStorageに保存しない方針を維持。

## 受入試験

- TypeScript/ViteビルドとFastAPI PythonテストはCI上で確認。
- Playwright/Chromiumでは、デスクトップのStudio編集表示、重複要確認タブ、話者一括リネーム、未保存時のZIP停止、保存後ZIP許可、検索・スマホ表示を人工データで検証する。
- こちらのブラウザテストは *Modal GPU実処理、自然な会議音声、常設URL、時間短縮評価* を証明しない。
