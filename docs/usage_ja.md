# 日本語ガイド：Google Colabでの使い方

## 最初に確認すること

このノートブックは、**録音ファイルを選ぶだけ**で文字起こしと（任意で）話者分離を行います。コード内のファイル名・出力先を書き換える必要はありません。

**必要なもの**：Googleアカウント、Google Colabを開けるブラウザ、処理対象の音声ファイル。**話者分離をする場合のみ**Hugging Faceのアカウントとモデルアクセス条件への同意・Readトークンが必要です。

**プライバシー**：録音ファイルはGoogle Colabのクラウドランタイムにアップロードされます。所属先の機密音声・個人情報を含む音声・本人同意が必要な録音は、組織の規程と利用条件を確認してください。モデルはHugging Faceからダウンロードします。コードには外部の文字起こしAPIへ録音を送る処理は含みません。

## 1. Colabでノートブックを開く

[Colabで開く](https://colab.research.google.com/github/ryotamatsuki/japanese-meeting-transcriber-colab/blob/main/notebooks/meeting_transcriber.ipynb)

1. `ランタイム` → `ランタイムのタイプを変更` を開く。
2. 利用可能なら `T4 GPU` を選び、保存する（利用枠はアカウント・混雑状況等に依存）。
3. 「① インストール」セルを**1回だけ**実行する。
4. **`ランタイム` → `セッションを再起動`** を選ぶ。
5. **インストールセルは再実行せず**、「①-2 動作環境チェック」セルから順番に実行する。

**重要**：インストールした直後にそのまま`import numpy`や`import pyannote.audio`を実行すると、更新前後のライブラリが混在して`_slice`エラーが出ることがあります。再起動で改善する場合があります。インストールセルを含む「すべてのセルを実行」は、初回には使用せず、上記の順番で操作してください。

## 2. 任意設定

通常は設定不要です。必要なときだけ以下を変えます。

| 設定 | 初期値 | 意味 |
|---|---|---|
| `ENABLE_DIARIZATION` | `True` | 話者分離を実施。単なる文字起こしなら`False` |
| `EXPECTED_SPEAKERS` | `0` | 正確な人数を把握している場合だけ指定。0は自動推定 |
| `MIN_SPEAKERS` / `MAX_SPEAKERS` | `0` | 人数の下限・上限。0なら指定なし |
| `LANGUAGE` | `ja` | 日本語。自動判定なら`auto` |
| `WHISPER_MODEL` | `large-v3` | 大きいモデルほど処理は重い傾向 |
| `GLOSSARY` | 空欄 | 固有名詞の認識ヒント。空欄で問題なし |
| `INPUT_MODE` | `upload` | ファイル選択ダイアログ。 `colab_existing`なら/contentの既存ファイル一覧から選ぶ |
| `SAVE_TO_DRIVE` | `False` | `True`なら結果ZIPをGoogle Driveにコピー |
| `DRIVE_OUTPUT_FOLDER` | `文字起こし結果` | Driveへ保存するときのフォルダ名 |

指定した話者数と、実際に判定できる人数が一致する保証はありません。

## 3. 録音を選択する

「③ 音声ファイルの選択」セルを実行して、録音ファイルを選びます。複数選択も可能です。

- 対応例：MP3、M4A、WAV、FLAC、OGG、MP4、WEBMなど（内部でffmpegが読み取れる形式）。
- ファイル名は自動で取得するため、毎回コードを書き換える必要はありません。
- Colabの左側ファイル欄にアップロード済みなら、`INPUT_MODE = "colab_existing"`で候補を一覧表示できます。

## 4. 話者分離を使う場合

1. [Community-1のモデルページ](https://huggingface.co/pyannote/speaker-diarization-community-1)でアクセス条件に同意します。
2. [Hugging Faceのトークン設定](https://huggingface.co/settings/tokens)でRead権限のトークンを作成します。
3. Colabの左側の鍵マーク（シークレット）に名前 `HF_TOKEN` で保存し、ノートブックのアクセスを許可します。未登録なら実行中に非表示入力が表示されます。

**トークンをコードに直接記載したり、スクリーンショットやGitHubに公開したりしないでください。**

## 5. 文字起こしと話者分離

残りのセルを上から順に実行します。録音の長さやGPU利用状況によって処理時間が変わります。

- Whisperが音声認識と単語単位の時刻取得を行います。
- 話者分離がオンなら、pyannoteが発言者の時間帯を推定します。
- 両方の時刻情報を照合し、発言を「話者1」「話者2」…に割り振ります。
- TXT・CSV・SRT・JSONを1つのZIPにしてダウンロードします。

「話者1」と表示されても、特定の実在人物・役職だと確認できたわけではありません。重複発話、短い相づち、似た声は誤る場合があります。

## 6. 出力と再実行

出力名には**元ファイル名と音声内容のハッシュ**を組み合わせるため、同名でも異なる録音は別フォルダになります。ZIP内に**元の録音音声そのものは含めません**。

処理完了後は、CSV・TXT・SRTなどを音声に照らして確認してください。音声認識・話者分離のJSONは同じColabセッション内での再処理に再利用できます。

**別ファイルを処理するとき**：設定は必要なら調整し、「③ 音声ファイルの選択」以降を再実行します。

**Colabの再起動・切断**：`/content` のファイルは永続保存ではありません。結果を保持したければZIPをダウンロードするか、任意でDriveへの保存を有効にしてください。

## エラーが出たら

| 症状 | 確認すること |
|---|---|
| `cannot import name '_slice'`（NumPy） | インストール後に**ランタイム再起動**。インストールセルを飛ばして動作環境チェックから再実行 |
| `metadata_errors`（PyAV） | 再起動後にPyAV 18系が読み込まれているかチェック |
| `libcublas.so.12` / `libcudnn.so.9` が見つからない | GPUが有効か、動作環境チェックのCUDAライブラリ読み込みが成功しているか確認 |
| Hugging Faceの401/403 | モデル利用条件への同意と、Readトークンの有効性・Colabシークレット許可を確認 |
| 話者が多すぎる | 実際の発言者数が分かるなら`EXPECTED_SPEAKERS`を設定して比較 |
| 文字起こしが不正確 | 録音状態・専門用語の`GLOSSARY`を調整し、必ず原音声で確認 |
| 処理途中で切断 | Colabの接続状態・メモリ/利用枠を確認。部分JSONからの自動再開は未実装 |

**この公開版には議事録要約・誤字の自動校正・発言者氏名の推定機能はありません。**
