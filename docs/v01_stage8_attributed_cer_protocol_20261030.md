# Stage v0.1-8 評価設計：最終的な話者付き日本語文字起こし

評価準備日：2026-10-30。リリース判定は **No-Go** を維持する。

## 背景と狙い
- Stage6：Community-1通常出力は排他的出力より10録音すべてで厳格DER/JERが改善。これは話者区間に限る。
- Stage7：重複候補の確認UIは実装・単一実録音A10 E2Eに合格。しかし重複区間の時間再現率47.79%であり見逃しがある。
- Stage8：**人間が読む最終的な話者付き文字起こしの品質**を、人手正解と定量比較する。現在のCER39.91%は単純連結した日本語文字列を参照するため、話者を取り違える誤りと重複発話の関係を正しく分離できない。

## 評価対象とデータ管理

- IngCrowd Japanese Themed Casual Conversation Corpus：人手ELAN付き2人対話10録音、CC BY-NC 4.0。**非商用研究・評価のみ**。県庁の実際の議事録や個人情報は一切投入しない。
- 同一音声・同一正解・Whisper large-v3/Community-1・A10・話者数2人を固定して再現する。
- 独立した10録音の評価は、`ryotamatsuki/ehime-kokubunsai-ai-poc/.github/workflows/stage8-attributed-cpcer.yml`。
- GitHub Actionsの成果物には**録音・ELAN逐語全文・推論出力全文を含めず**、数値とEAF SHA256のみ残す。
- 今回の結果は一般的な行政会議・会議室マイク・4話者の成績ではない。

## 指標1：speaker-attributed character-permutation CER（cpCER）

- 参照話者ごとの人手文字起こしと、予測話者ごとの最終文字起こしを、それぞれ時刻順に連結する。
- NFKC+casefold、空白・Unicode句読点/記号除去後、文字単位Levenshtein距離を計算。**全録音に対し1回だけ話者の一対一ラベル置換**を最適化し、誤り合計÷参照文字数をcpCERとする。
- 予測話者数の超過ラベルと「話者不明」の文字は挿入誤りに算入し、正解話者が予測されなければ削除誤りに算入する。都合よく重複話者テキストや「話者不明」を無視しない。
- cpCERはDERや一般的なCERと同じではない。日本語の単語分割が必要なcpWERとは異なる。
- 推論の補正を比較する場合、同一の文字列を使って話者割当てのみ変更した条件と比較する。認識テキスト自体が変わった場合、話者割当て効果を単独では主張しない。

## 指標2：重複部分の時刻局所化「参考値」

- 人手ELANから真の重複発話区間を抽出。開始・終了時刻を基に、予測発言を重複部分・非重複部分に分ける。
- **発言単位の時刻に基づく近似分割**なので、重複の一部しか含まない発言も全体が重複側に分類される。厳密な重複単語CERやcpCERと呼ばない。
- 重複側の認識文字数と参照文字数、誤り、非重複側の誤りを別々に記録。重複発話の取りこぼしや録音条件の影響を探索するための指標に限定する。

## 指標3：同一ASRの話者帰属アブレーション（探索3録音）

- `scripts/evaluate_attribution_ablation.py` でWhisperの推論文・タイムスタンプを凍結。基準は従来Exclusiveの単語→話者割当てで生成した最終文字起こし。
- 比較は同一Community-1の通常区間から単語時間との重複を集計して**1つの話者ラベルだけ**を選ぶ実験的ルール。これにより原文を重複複製せずに話者帰属だけを変える。
- [ワークフロー](https://github.com/ryotamatsuki/ehime-kokubunsai-ai-poc/blob/eval/meeting-transcriber-stage1-20261030/.github/workflows/stage8-attribution-ablation.yml) ではまず01、05、08の3録音を探索的に比較する。3件では採用を決めず、結果が良好なら10件すべてへの拡張を検討する。
- 必ず**誤差を悪化させる事例・取りこぼしの限界・重複発話時の誤検出リスクを明示**する。単一マイクの混合音声では、話者活動区間を増やしても2人分の独立した文字列が自動で得られるわけではない。
- 採用条件は、実際の話者付きcpCERの改善を証明し、品質の下振れと編集手間を確認すること。単なるDER改善をもって採用しない。

## 現時点の採否
- 上記は**評価設計と実装**であり、実際の評価値が取得・検証されるまで改善率を主張しない。
- 実用UIのExclusive単一話者帰属と人手重複候補確認を維持する。再ASRによる新しい文章の自動追加、話者IDの自動改変を行わない。
- v0.1の暫定品質基準や長時間保存・費用管理・自動削除などの公開条件は引き続き独立に判定する。
