## 最重要の新規発見
- 10録音の参照上の話者活動合計 **8,262.109 speaker-seconds**、重複発話により追加で必要な話者活動 **1,601.568 speaker-seconds**。
- 「どの時点でも発言者1人」のexclusive出力には、**DER下限 19.38%**（重複発話が漏れるだけでも到達不能な下限）が生じる。個別録音の下限中央値は **22.32%**。
- 観測DERの合算（micro DER） **28.52%**。録音別DERの中央値 **32.12%** は別の統計量で、混同しない。
- 観測 missed detection **1,988.72秒**のうち、参照の二話者同時活動のみから不可避な最小量が **1,601.57秒**。約 **80.53%** は構造的な重複発話の表現不能だけで説明できる。
- 観測DERの総誤り時間はMiss **1,988.72秒**、Confusion **276.96秒**、False alarm **90.74秒**。それぞれ **84.40%／11.75%／3.85%**。
- 人手の正規化文字数 **43,954字**に対しWhisper出力 **30,296字**、文字数比 **68.93%**。ただし、認識文字数不足は重複・参照の注釈規則・音声取りこぼし等の複合であり、ASR単体の欠落率ではない。
- 録音別簡易CER中央値 **39.91%**。2人の重複発話を開始時刻順で1本に連結した擬似CERであり、cpCERではない。

## 解釈上の制約
- ここでの数学的下限は**参照ELANの発話区間に対する基準**であり、録音中の実際の発声だけを自動判定したものではない。人手区間が休止や笑いを含むことがあり、実利用に転用する前に注釈規則を監査する。
- Exclusiveをregular出力へ差し替えたら必ずDERが改善するわけではない。regularの重複発話には誤検出もあり得る。置換判断は10録音のDER/JER/混同/誤検出を同条件で比較してから。
- 標準出力の重複区間をそのまま従来の単一テキストへ割り当てても2人分の同時発話が自動的に認識できるわけではない。話者の二重ラベル、対象話者別ASR、分離音源による再認識等を別に測定する。
- 10件は同一コーパスの対話であり、10組の独立話者・行政会議・5人会議の代表サンプルではない。非商用ライセンスのため製品実験との境界に留意。

## 長時間Web E2Eの判定
- 初回（run 41026648129）はアップロード→A10推論→2話者認識→長時間結果取得まで通過し、一括編集保存APIで失敗。HTTPステータスを保存していないため根本原因未確定。
- 同じ種類の反復公開音声の再試験（run 41028143023）ではHTTP E2E 509.92秒、GPU 480.09秒、1097発言、最終発言3592.84秒、全文編集保存・ZIP・削除まで成功。
- 推論が成功したことと、保存障害の根因が解消したことは別。異なる録音、失敗時HTTPステータス、発言時刻のゼロ/負数、コンテナのVolume同期、再試行・冪等性を確認する。

## Stage 5の技術選定と採否
1. **最優先：Community-1 の regular speaker diarization と exclusive 出力の厳格なDER/JER比較**。既存モデルの二話者活動情報を保存し、誤検出増と検出漏れ減を各録音で確認する。
2. **次点：重複発話を含む区間への対象話者別のASR**。公開コーパスには話者別音声があるため、oracle分離音源の実現可能な上限と混合音声ASRを比較して改善余地を把握できる。
3. **日本語CTC forced alignmentは第三候補**。語時刻の精度向上と話者帰属の誤りへの影響を個別に検証。上記の表現不能な同時発話を直接は解決しない。
4. **モデル交換・beamの既定変更は保留**。独立録音で精度改善を示すまで、現行baseを変更しない。
5. **Web v0.1のRelease判定はNo-Go**。CER15%以下、DER30%以下の暫定目標、Web編集保存の失敗再現、実ブラウザ操作と24時間削除監査が未解決。
