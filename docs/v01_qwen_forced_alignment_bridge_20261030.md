# Qwen3-ASR の時刻・話者統合に関する試験（Stage 11 準備）

2026-10-30、**既存ベータへ未採用**。公開不可（Release No-Go）。

## 検証の目的

Stage 10では日本語2人対話10録音に対し、Qwen3-ASR-1.7Bの平坦化CERがWhisper large-v3より全件低かった（中央値39.91%→31.44%）。ただし同時発話の順序を含むフラットなCERであり、既存のブラウザが必要とする発言単位の時刻と話者を表現できていなかった。

次に、日本語対応のQwen3-ForcedAligner-0.6Bを使用し、Qwenが認識したテキストへ**単語単位の時刻**を付け、既存Community-1の排他的話者区間と統合する。元のテキストを失わずに既存の字幕・編集行・話者ラベル形式へ変換可能か、人手ELANのcpCERで確認する。

- 公式資料：[Qwen3-ASR / Forced Aligner](https://github.com/QwenLM/Qwen3-ASR)、[Qwen3-ForcedAligner-0.6B](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B)。
- 研究モデルはQwen3-ASR-1.7B＋Qwen3-ForcedAligner-0.6B、Community-1排他的話者区間。
- 入力はIngCrowdの非商用日本語2人対話01/05の16kHzモノラル。**CC BY-NC 4.0**。
- Qwen入力を約30秒ごとに区切り、個々の区間へ強制アラインメントを行う。`chunk.offset_sec`を合算して録音全体の絶対秒数へ変換。
- 文字を自動生成・削除せず、既存の`transcriber.alignment.assign_and_group`で話者ラベルを割り当てる。
- モデル推定の未確定部分を人手正解から補正することはしない。音源分離・別ASR追加もなし。
- `scripts/qwen_timing_bridge.py`で、区間時刻・時刻順序・録音末尾カバレッジ、正規化日本語全文の完全一致を**実行時に検証**。文字が欠けたり単語時刻が不正なら本番変更をせず試験失敗とする。
- `scripts/evaluate_qwen_attributed_bridge.py`で人手ELANと対照し、話者置換最小cpCERと全文連結CERを両方計算する。
- GPU処理には一時的な2つの研究ジョブを使用し、文字・音声をGitHub Artifactやログへ出力しない。数値指標・ハッシュ・失敗原因区分のみ保全。
- 既存のWhisper stage8 cpCER中央値46.89%と、別日時のQwen試験2件を単純に比較せず、同じEAF SHA256を確認した録音別基準を使用する。

## 受入判定条件

1. Qwen3-ASR＋ForcedAlignerが同じ録音から時刻付きの全単語を出力し、正規化全文が欠落なく保存される。
2. 排他的Community-1話者区間と統合した発話行を既存形式に変換できる。
3. 元のELAN参照ハッシュを確認し、人手正解へのcpCERで従来Whisperの同録音と比較する。
4. 単語時刻の先頭・末尾、GPUの追加負荷、音声の長時間化に伴う不具合を明示する。
5. まず2録音探索。結果が良ければ10録音とWeb経由60分の再検証へ進むが、研究2録音だけで既定モデルを変更しない。

## 残る課題

- 3〜4話者や会議室集音への外的妥当性。
- 60分入力のQwen推論・アラインメント実行時間とモデルメモリ、課金。
- 複数利用者、ジョブ復旧、24時間削除の独立検証。
- 修正負担が50%減少したかの実利用者検証。
- 元の保存失敗の根本原因の特定。
